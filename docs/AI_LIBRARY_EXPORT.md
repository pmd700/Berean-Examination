# AI library export

Home's **AI Export** button replaces Mass Backup. It saves one UTF-8 Markdown file through the existing native Save As bridge. It runs locally and never sends content to an AI or a website.

The file contains every saved book page and page title, keyword explanation, timeline event description, Bible commentary, chapter study writing, Knowledge Web card and canvas text object. Closed sections, comments, tooltips and footnotes are expanded. Drawing text elements are included when available; images, attachments and visual strokes retain references/captions with explicit extraction limits. Binary media and external pages are not fetched or transcribed.

The inventory and source index give stable record references. Notes use `note:<id>/page:<number>`, timelines retain their stored event IDs, cards use `web:<id>/card:<id>`, and commentaries use the existing Annotation ID and `commentaryLinkHref`. Commentary links include their canonical source edition. Hyperlinks, embeds, keyword mentions, timeline links and graph connections are written into a separate Relationships section; unresolved targets remain visible with a warning. Explicit graph direction/labels are preserved without assuming that connections establish support or causation.

Timeline events are sorted chronologically using the existing astronomical-year date model (year 0 = 1 BCE). Start/end dates, precision, approximate dates, ranges, equal-date groups and previous/next date groups are explicit. Undated or malformed legacy events are retained with their original data and a warning. The Knowledge Web Markdown exporter supplies the readable board/diagram; its normal individual export still includes the exact restore payload, while AI export omits that opaque envelope.

Before exporting, BEX drains registered editors and waits for entity saves, including commentaries and keywords. The desktop reads all collections in a single read transaction using ID pagination, so other windows cannot produce a mixed snapshot. Older bridges use validated cursor pagination. Mutations during conversion trigger a fresh read; repeated changes or failed reads/saves block the export instead of generating a partial file. Conversion yields between records so progress and cancellation remain usable. Private webs must be unlocked; each is decrypted with its own existing key without changing the active editor's encryption context. Passphrases and encrypted payloads do not enter the export. The native 128 MB snapshot and renderer 64 MB output ceilings fail explicitly rather than truncating content.

Markdown code blocks and inline code remain literal, including significant whitespace. Markdown reference links are indexed, media links are recorded with captions, and embedded binary data is omitted. Typed graph endpoints distinguish cards from routing points even when their numeric IDs overlap. Canvas embeds reference their actual timeline or linked Knowledge Web; missing parent webs block export instead of silently dropping their children.

The dedicated Mass Backup dialog, renderer ZIP builder, folder settings, archive manager and five IPC endpoints are removed. Shared pagination, individual note/web exports, import compatibility and vault backup/restore services remain in use. Existing user archives are not deleted.

Verification includes DOM conversion and Home-dialog tests, invalid/read/save/private-web/cancellation cases, existing Markdown restore tests and `electron tools/run-ai-library-export-proof.cjs`. The native proof uses a disposable encrypted library, real guarded IPC and the actual Home control; it confirms all 12 synthetic book pages and 1002 keywords survive in a single file, with correct commentary IDs/editions, typed canvas connections and timeline embeds, and no changes to the original writing. Untrusted snapshot requests, locked vaults, incomplete reads, save cancellation and synthetic disk failures cannot produce a successful export.
