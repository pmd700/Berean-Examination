# Local Scripture annotation display

User settings are available only from the Home header. The new setting `scripture_annotation_display` lives in the existing local-owner SQLite preferences; it uses no OAuth or remote account service. Its default is `gutter`. Choosing `hover` restores underlined text with the original hover preview. Successful writes update other mounted reader tabs; failed writes leave the previous preference in place and show an error.

Both modes use the same encrypted Annotation entities, selection token indices, content editor, and autosave. Gutter Add/Edit mounts `TEXT_EDITOR_MACHINERY.jsx` directly inside the existing card; the popup annotation window is exclusive to hover mode. The full editor retains formatting, links, lists, tables and Markdown shortcuts. The card shows save status and Done/Delete controls. Done and switching to another note drain pending writes first; failures keep the draft open. New gutter drafts have stable record IDs from the start, and dismissing an empty new draft removes it. Copy reads the current editor content while editing. There is no writing migration. Gutter cards are created only for annotation ranges present in the current reader, so replacing a search or changing translations does not leave unrelated commentary in the rail. In gutter mode the reader sits on a surface with unrestricted two-dimensional camera movement and pinch zoom. The note rail is 1040px wide on larger windows, limited to the window width minus 48px in Split View, and sits outside the Scripture card. Commentary renders in full without an internal height cap or repeated selected-Scripture preview. Cards at nearby ranges initially stack without overlapping. Cards keep their natural content height until explicitly resized; their canvas positions do not stretch the Scripture card or add blank page space. The Scripture card and attribution keep their natural height, so long notes do not add blank space inside the card. Existing scroll buttons move into the reading flow when the rail is active. They appear only when the Scripture body is taller than the tab pane; search controls, attribution and tall gutter notes do not enable them. Passage/window resizing rechecks the fit, and the existing smooth scroll and slow fade-in remain.

Pixel-mode wheel gestures move the canvas in both axes, following trackpad momentum without any distance or direction boundary. Capture-phase handling lets one gesture continue across note content. Ctrl/Meta wheel pinches zoom the canvas around the pointer without changing browser zoom or saved font settings. Touchscreen pan and pinch require two touches; a single finger retains native text interaction and scrolling. Line-mode mouse wheels remain native. Chromium exposes no finger count for wheel events, so desktop trackpad gestures use the same pixel convention as Knowledge Webs. No pointer/mouse drag pans the workspace. Resize and tab changes preserve the camera. The purple focus icon follows the active reader edge, fades in over 2 seconds and out over 1.5 seconds, and restores the default camera and zoom. Arrow keys pan a focused canvas in four directions; Home recenters. Hover mode retains its existing layout.

Gutter mode suppresses the annotation pen icons, shading, and reading-text underlines; independent personal highlights remain visible. Each entirely selected verse gets its own arrow to the verse number box. Partial selections keep a precise text anchor. The branches share one green routing dot, which bends the purple quadratic connectors together. It lies on the actual curve at its midpoint. Pointer release persists the optional `Annotation.gutter_route` object (`x`: lateral bend relative to the endpoint gap, `y`: vertical offset in pixels). Pointer cancellation restores the last saved bend. Arrow keys adjust the dot, Shift increases the step, and double-click resets it. The desktop entity store rejects invalid/out-of-range positions. Existing encrypted backups retain this field automatically.

Short gutter cards start around 320px wide (bounded by the rail on narrow windows), and editors start at one line. They size to their writing; longer paragraphs can expand to the full rail width, and height has no cap. Cards remain aligned to the reader-facing edge of the gutter. Delete/Done use trash/check icons, and save status uses a pending spinner or a saved SD-card icon. Tooltips and accessible labels remain. Actual failed writes show a separate error icon until editing or retrying, rather than implying that a save succeeded or is still running.

Verification: `npm run annotation-gutter:proof` uses a disposable Electron profile/library, synthetic API responses, the actual guarded entity/owner IPC, and SQLite persistence. It checks compact/expanding editors, pointer dragging/cancellation, stored bends after reopening, Home-only settings, hover restoration, private writing preservation, and desktop/Split View geometry. It never opens the user's library or API credentials.

Commentary links carry the canonical annotation version (`API:<edition ID>` for API.Bible), with the edition named in the tooltip and copied link label. Opening a link resolves the saved annotation before fetching Scripture. This also repairs older links without a version parameter and preserves adopted local study identities. Missing notes still open the explicitly linked API edition. A cancelled or superseded source lookup cannot replace a newer search, and failed lookups do not silently switch to BSB.

A purple six-dot handle on the left edge of each gutter card moves the whole note horizontally and vertically. Arrows update in the same render, retain their Scripture targets and attach to the edge facing the target. Pointer capture keeps dragging when the cursor leaves the handle; cancellation rolls back without saving. Arrow keys move the focused handle (Shift moves farther); double-click restores automatic placement. Release persists the optional encrypted `Annotation.gutter_position`. Existing records remain offsets from automatic placement; new manual moves store an absolute canvas y coordinate with `absolute: true`, preserving their position when the card changes height. Coordinates and cable bends are finite numbers without distance caps. Position and cable-bend writes share a serialized queue; failed moves restore the last successful position. The existing shared editor stays mounted while dragging. Card movement never changes width or height. The canvas moves independently of the Scripture body.

Reading controls contain independent Scripture and Notes text-size sliders. `scripture_notes_text_size` uses the existing local-owner preference storage and synchronizes mounted reader tabs. Its own CSS token sizes gutter writing, inline editing, and the legacy hover preview/popup without changing the saved text or Scripture size. Verse number labels use their intrinsic width and do not wrap, including two- and three-digit numbers at the largest Scripture size.

Four corner handles resize each card's width and height independently while holding the opposite corner fixed. The optional encrypted `Annotation.gutter_size` stores these dimensions; size and position are saved atomically and roll back together on failure or pointer cancellation. A manually shortened card scrolls its writing internally in both reading and editing modes. Double-clicking a corner restores natural content sizing, which shows the full writing without an internal cap. Movement and resizing use canvas coordinates at the current zoom, so the handles and arrows remain aligned.
