We need to fix our MFA login flow without changing the overall auth architecture.

Current confirmed situation:

- Our app uses a custom login UI, not Auth0 Universal Login.
- The frontend submits login to POST /api/auth/login.
- The backend route is in server/auth0.ts.
- That backend route forwards the user’s email/password to Auth0 /oauth/token using the password grant flow.
- Auth0 is currently responsible for password verification.
- Our Postgres database does not store password hashes.
- After I enabled MFA in Auth0, Auth0 started returning mfa_required.
- Our backend relays that response back to the frontend.
- The frontend currently treats “Multifactor authentication required” as a normal red login error, which breaks the login experience.

Decision:

We are keeping the current Auth0-based auth architecture.

Auth0 should continue handling:
- password verification
- MFA enrollment
- MFA verification
- token issuance

Our app should continue handling:
- custom login UI
- app user records in Postgres
- roles/admin/access keys
- study data and app-specific data

Do NOT:
- migrate away from Auth0
- build first-party password storage
- add bcrypt/argon2 password auth in Postgres
- build our own custom TOTP/MFA system
- store MFA secrets in our database
- switch to Auth0 Universal Login unless absolutely necessary

Goal:

Make our current custom login flow properly continue when Auth0 returns mfa_required.

Expected user experience:

1. User enters email/password on our current login page.
2. Backend sends credentials to Auth0 like it already does.
3. If Auth0 login succeeds normally, the user enters the app as usual.
4. If Auth0 returns mfa_required, the app should not show it as a login failure.
5. Instead, the user should be moved into a clean MFA verification step.
6. User enters their MFA code.
7. Backend completes the MFA verification with Auth0.
8. If MFA succeeds, the user is logged in normally.
9. If MFA fails, show a clean user-friendly error.
10. If the MFA session expires, send the user back to sign in again.

Please inspect the current Auth0 login flow and implement the missing Auth0 MFA continuation flow in the cleanest way for this architecture.

Also check whether our Auth0 application has the needed MFA grant/settings enabled for completing MFA through this custom flow.

Keep the implementation minimal, safe, and consistent with the existing codebase. Do not rewrite the whole auth system.
