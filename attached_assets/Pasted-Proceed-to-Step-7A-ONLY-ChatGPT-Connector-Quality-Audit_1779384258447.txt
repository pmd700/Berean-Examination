ChatGPT.com successfully connected to the deployed MCP endpoint:

https://bereanexamination.com/mcp/brain

The connector currently exposes four read-only tools:
- search_second_brain
- get_brain_context_pack
- get_card_context

- sources array was empty
- returned card snippets contained HTML
- some cards were loosely related
- citation format is still raw card IDs
- source/card data may need better normalization for ChatGPT answers

Goal:
Audit the current ChatGPT connector quality from the server/tool perspective.

Tasks:

1. Test representative queries.

Run tool-level tests against the deployed MCP server using MCP_BRAIN_TOKEN or local equivalent.

Test these queries:
- God
- gospel
- Catholicism
- justification
- faith alone
- hell
- Christ paid for sins
- universe brute fact
- BGV theorem
- Angel Catholicism

For each query, record:
- number of sources returned
- number of cards returned
- number of connections returned
- whether results look relevant
- whether snippets contain messy HTML
- whether the result has enough context for ChatGPT to answer well

2. Inspect result quality.

For each query, identify:
- best matching cards
- weak/noisy matches
- missing obvious matches
- whether source coverage is empty or weak
- whether connections help or clutter

3. Audit snippets.

Check whether card/source snippets are clean enough for ChatGPT.

Look for:
- raw HTML tags
- broken entities
- huge chunks
- duplicate snippets
- empty snippets
- irrelevant snippets
- Bible links overwhelming the text

4. Audit citation usability.

Check whether returned IDs/titles are enough for ChatGPT to cite clearly.

Evaluate whether we should later return:
- card title
- card id
- web name
- card type
- tags
- source title
- source id
- direct app URL if available

5. Audit tool descriptions.

Review MCP tool descriptions and parameter descriptions.

Check whether ChatGPT is likely to understand:
- when to use search_second_brain
- when to use get_brain_context_pack
- when to use get_card_context
- when to use get_source_context

Suggest improvements, but do not implement them.
