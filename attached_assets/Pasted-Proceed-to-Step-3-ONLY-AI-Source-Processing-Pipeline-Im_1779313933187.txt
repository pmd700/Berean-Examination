3. Add route:

POST /api/brain/sources/:id/process

Behavior:
- require authentication
- load the source owned by the current user
- reject if not found
- reject if source is already processing
- allow processing if status is unprocessed or failed
- optionally allow reprocessing a processed source only with query/body flag force=true
- set processing_status = processing before calling AI
- call AI with the source title, source_type, source_url, and raw_text
- save the structured result to metadata_json.ai_processing_v1
- set processing_status = processed
- set processed_at = now
- return the updated source

5. AI prompt behavior

The processing prompt should follow these rules:

- Be faithful to the raw source.
- Do not claim the user believes something merely because a source says it.
- Distinguish source claims from user beliefs.
- Do not invent Bible references, quotes, authors, or claims.
- If the source is theological, extract scripture references, doctrines, objections, and theological positions carefully.
- If the source is CRM/person-related, extract people and relationship context carefully.
- If the source is a journal entry, extract themes and questions, but avoid overclaiming.
- Return structured JSON only.

- actor = 'ai'

- action_type = 'source_processed'
- actor = 'ai'
- entity_type = 'brain_source'
- entity_id = source id
- summary = "AI processing completed for source: [title]"
- after_json may include summary, key_points count, possible_card_drafts count, possible_connection_drafts count
- do not store raw_text in brain_logs

When processing fails:
- action_type = 'source_processing_failed'
- actor = 'system'
- entity_type = 'brain_source'
- entity_id = source id
- summary = short error summary
- do not store raw_text in brain_logs
