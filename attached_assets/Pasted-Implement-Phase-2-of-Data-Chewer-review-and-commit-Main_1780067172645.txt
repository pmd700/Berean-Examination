Implement Phase 2 of Data Chewer: review and commit.

Main idea:
Data Chewer currently produces read-only proposed changes. Now make those proposals actionable inside Brain Chat.

Keep Data Chewer lightweight:
- No new page
- No separate intake form
- No Raw Source Inbox workflow
- No extra required fields
- Keep Data Chewer as a smart button/mode inside Brain Chat

After chewing raw input, show the results as a GitHub-inspired review panel inside Brain Chat.

UI/UX direction:
Make the proposal review feel like a clean GitHub pull request / commit review.

The user should see:
- a compact source summary at the top
- detected source type and confidence
- proposed cards grouped under “New Cards”
- proposed connections grouped under “New Connections”
- warnings / duplicate risks grouped separately
- a simple changelog preview
- clear Accept / Reject controls per item
- a sticky or clearly visible “Commit accepted changes” action

Visual style:
Use a minimal GitHub-style aesthetic: clean bordered cards, subtle dividers, compact rows, status badges, muted neutral colors, small metadata text, and clear green/red accept/reject states. Avoid colorful AI-slop styling. Make it feel like reviewing a serious knowledge-base diff.

Behavior:
The user should be able to accept or reject individual proposed cards and connections, then commit only the accepted items into the selected Knowledge Web.

On commit:
- create only accepted cards/connections
- preserve source relationship for citation/history
- store a simple changelog/decision summary
- never add rejected items to the live graph
- never mutate the graph without explicit user approval

Important boundaries:
Do not change schema unless absolutely necessary.
Do not touch MCP.
Do not touch Auth0/OAuth.
Do not touch import/export, backups, Mermaid, or hidden restore blocks.
Do not alter unrelated Brain Chat behavior.
Do not make Data Chewer feel like a form again.

Final report:
- What changed
- Files changed
- New/changed API behavior
- UI/UX changes made
- How source preservation works
- How rejected items are handled
- Tests/build result
- What was intentionally left untouched
